# Icons

Original icons, drawn by hand on a 12 x 12 pixel grid in one colour, and one brand: GitHub's mark, redrawn on the
grid, for linking to a repository (it stays GitHub's trademark). They share their pixel with Pixel Bop and the
candy box, so an icon, a letter and a button corner are made of the same squares. At the default pixel an icon is 24
CSS px.

## Usage

Every form below draws the same paths. Pick the one that suits the page.

**Sprite.** One cached file for every icon. Copy `@jaatster/blip-icons/sprite.svg` into your static files (an external
`<use>` must come from the same origin as the page). Each symbol carries its own viewBox, colour and crisp edges.

```html
<svg class="blip-icon" aria-hidden="true"><use href="/assets/sprite.svg#blip-icon-heart"/></svg>
```

**Inline SVG.** No request at all. Copy a file from `@jaatster/blip-icons/svg/` or paste its path:

```html
<svg class="blip-icon" viewBox="0 0 12 12" aria-hidden="true"><path d="M5 2h2v3h3v2H7v3H5V7H2V5h3z"/></svg>
```

**JavaScript.** `iconSvg` returns the same markup as a string; `icons` holds the path data, typed by `IconName`.

```js
import { iconSvg, icons } from "@jaatster/blip-icons";

button.innerHTML = `${iconSvg("trash")}Delete save`;
status.innerHTML = iconSvg("success", { label: "Saved" });

// Canvas: one icon pixel is one Blip pixel.
ctx.scale(pixel, pixel);
ctx.fill(new Path2D(icons.heart));
```

**Element.** `<blip-icon>` renders the inline SVG in light DOM and keeps it in step with its attributes. If the page
already holds the `<svg>` (rendered on the server), the element adopts it, so the icon shows before the script runs.

```html
<script type="module">import "@jaatster/blip-icons/element";</script>

<blip-icon name="bell"></blip-icon>
<blip-icon name="heart" label="Liked"></blip-icon>
<blip-icon name="gamepad" data-size="lg"></blip-icon>
```

**React.** `@jaatster/blip-react` will export `<Icon name="heart" label="Liked" />`, generated from the same data.

**Native apps and design tools.** `dist/svg/` holds one 24 x 24 file per icon: import them as Android vector
drawables or into an iOS asset catalogue as template images, so the tint colours them. `dist/icons.json` lists every
icon with its category, tags and path, for search, docs and the Figma library. Draw them at whole multiples of 12 px
(12, 24, 36, 48) so every pixel stays square.

## Sizing

| | Pixels | CSS px at the default pixel |
|---|---|---|
| default | 12 x 12 | 24 |
| `data-size="lg"` | 24 x 24 | 48 |

Sizes follow `--blip-pixel`: on a section with a 3 px pixel an icon is 36 CSS px. The default suits text, buttons and
lists; `lg` is for empty states, feature tiles and game HUDs. Never set a size that is not a whole number of pixels:
an icon at 30 px blurs.

## Colour

An icon is one colour, `currentColor`: set `color` on it or on its parent. In a candy button it takes the label's
colour, so it passes the same contrast check. Don't set `fill`. The usual rules hold: ink, never black, and yellow
only for focus, coins and stars.

## Accessibility

- **Decorative by default.** An icon next to text that says the same thing is `aria-hidden="true"`; that is what
  `iconSvg`, `<blip-icon>` and the sprite example produce.
- **Meaningful on its own?** Give it a label: `iconSvg(name, { label })` or `<blip-icon label="…">` makes it
  `role="img"` with that name.
- **Icon-only buttons** name the button, not the icon: `<button aria-label="Delete save">` with a hidden `trash`.
  Name the action, not the picture.
- **Never the only signal.** Info, success, warning and error differ in shape (circle, circle, triangle, octagon) as
  well as colour, and always come with words.
- **High contrast.** `currentColor` follows Windows' system colours with no extra CSS.
- **Targets.** An icon is 24 CSS px; anything you can press is a button, at least `--blip-target-min`.

## Drawing a new icon

Icons are pixel maps in `src/<category>.icons`, one file per category. A block is a header and exactly 12 rows:

```text
@ heart tags: love, like, liked, favourite, health, life
............
............
..XXX..XXX..
.XXXXXXXXXX.
.XXXXXXXXXX.
.XXXXXXXXXX.
..XXXXXXXX..
...XXXXXX...
....XXXX....
.....XX.....
............
............
```

`X` is a pixel and `.` is empty. Names are kebab-case and unique across all files; name what the icon shows
(`trash`) and put what it is used for in the tags (`delete, remove`). Variants end in `-outline`, `-off` or `-plus`.
A new file is a new category, listed last until it is given a title in `scripts/build.mjs`.

### The rules

The set is drawn like the item icons of a 16-bit game: bold silhouettes that read at 24 px, not thin line icons.
A one-pixel line at this size is two CSS px, and a one-pixel diagonal is squares touching at their corners, which
reads as dots.

1. **Grid.** Draw inside the middle 10 x 10 and leave the outer ring empty. The build warns when an icon touches it.
2. **Solid first.** An object is a filled silhouette. Its details are cut out of it, as empty pixels, not drawn on
   it: the slots of the bin, the flap of the envelope, the keyhole of the lock. Two cut-outs at most; a third is
   noise. A one-pixel gap is fine; a one-pixel line is not.
3. **Two pixels thick.** Every line is at least two pixels thick, diagonals too: the thinnest diagonal steps one
   column per row with two pixels in each row, like the chevrons. Every pixel touches another one above or below it
   and another one beside it, except at the very tip of a point.
4. **The build checks 3.** It stops at a one-pixel line of three or more pixels (flat, steep or diagonal) and at a
   lone pixel that touches nothing on a side, and names the row and column. An icon that truly needs a thin line
   says so in its header, `@ name thin tags: …`; none of the set does.
5. **Diagonals step evenly.** Only 1:1, 2:1 or 1:2, and the same step all along a line: never 1-2-1-3.
6. **Hollow only where it means something.** The `-outline` variants are the "off" half of a toggle (`heart-outline`
   to `heart`, `star-outline`, `bookmark-outline`); things that *are* frames (maximize, minimize, the brackets) stay
   frames. Their walls are two pixels.
7. **The circle.** Round status icons share one solid circle, ten across, with their symbol cut out of it: info,
   success, error, alert, help and the clock. The alarm's face is eight across, to leave room for its bells and feet.

   ```text
   ....XXXX....
   ..XXXXXXXX..
   .XXXXXXXXXX.
   .XXXXXXXXXX.
   .XXXXXXXXXX.
   .XXXXXXXXXX.
   .XXXXXXXXXX.
   .XXXXXXXXXX.
   ..XXXXXXXX..
   ....XXXX....
   ```

8. **Corners.** Round objects drop their corner pixels, like the candy box; paper and screens keep square corners.
9. **Slashes.** An `-off` icon is its icon with a two-pixel slash from the top-left pixel (1, 1) to (10, 10) and a
   one-pixel gap cut along its lower-left side.
10. **Squint.** Filled in solid, the silhouette alone still says what it is, and differs from its neighbours: file,
    document and clipboard; cloud and cloud-upload; the three battery levels.
11. **Centre.** Centre the shape. A part with an odd width cannot centre exactly, so it leans half a pixel left or
    up. The optical centre wins: `play` sits a pixel right; a family keeps its shared part still (`volume`,
    `volume-low` and `mute` keep the speaker where it is, so they swap without a jump).
12. **Families share geometry.** Arrow heads are the chevrons; carets are filled chevrons; status icons share the
    circle; one cloud serves the devices and the weather; the `-off` slash is always the same.
13. **No brands and no words.** Generic glyphs only (`globe`, `rss`, `code`, `share`); no logos, including
    trademarked symbols such as Bluetooth's. Letters appear only in the text-format icons (bold, italic, underline).

### Check it

```sh
pnpm --filter @jaatster/blip-icons build      # validates the maps, traces them, writes dist/ and the gallery example
node scripts/gallery.mjs
node scripts/shoot.mjs .tools/shots/icons "/specimen/gallery.html?only=icons=day" \
  "/specimen/gallery.html?only=icons&scheme=night=night" --full
node scripts/shoot.mjs .tools/shots/icons "/specimen/gallery.html?only=icons=zoom" --scale 2 --width 800
```

The build stops on a broken map and names the file, the line and the fix: a row that is 11 wide, a stray character,
a name used twice, a block without tags, a one-pixel line or a lone pixel. It traces each icon into one path (outlines clockwise, holes anticlockwise,
straight runs merged, whole numbers only) and draws the path back onto the grid to prove it covers exactly the
pixels you drew.

Then look at it among its neighbours, at true size, in Day and Night: does it weigh the same, sit on the same centre,
and read without its name?

## Do and don't

- **Do** pair icons with words in navigation, forms and status messages.
- **Do** use `-outline` for the "off" state of a toggle (`heart-outline` to `heart`).
- **Don't** scale an icon by a fraction, rotate it, or draw it at a size that is not a multiple of 12 px.
- **Don't** colour part of an icon: it is one colour. Multi-colour candy glyphs and sprites belong to the game kit.
- **Don't** redraw an icon inside a component's CSS: components mask their own small glyphs; content icons come
  from this package.

## API

| Export | What |
|---|---|
| `@jaatster/blip-icons` | `icons` (name to path data, frozen), `type IconName`, `iconSvg(name, options)` |
| `@jaatster/blip-icons/element` | Defines `<blip-icon>` (class `BlipIcon`) |
| `@jaatster/blip-icons/sprite.svg` | Every icon as `<symbol id="blip-icon-<name>">` |
| `@jaatster/blip-icons/svg/<name>.svg` | One file per icon, 24 x 24 |
| `@jaatster/blip-icons/icons.json` | `categories` and `icons` (`name`, `category`, `tags`, `path`) |

`iconSvg(name, { label?, size?, class? })` returns `<svg class="blip-icon …">` with a `viewBox="0 0 12 12"`, a
24 x 24 (or 48 x 48) size for pages without the core CSS, and `aria-hidden="true"` unless it has a label. It throws
a `RangeError` for a name that is not an icon.

| `<blip-icon>` | |
|---|---|
| `name` attribute and property | The icon. An unknown name draws nothing and warns once (`BLIP-I001`). |
| `label` attribute and property | Its accessible name. Without one the icon is hidden from assistive technology. |
| `data-size="lg"` | Twice the size. |

The element has no events and no listeners: it only draws. The `.blip-icon` class (size, colour, crisp edges) lives
in `@jaatster/blip-core`. All the icons together are about 5.6 KB gzipped as JavaScript; the element adds under 1 KB.
